# Entity-Relationship Diagram (ERD) - Textual Representation

## 1. Introduction

This document provides a detailed textual representation of the Entity-Relationship Diagram (ERD) for the "AI-Powered Learning Experience" platform. It defines the key data entities within the system, their attributes, and the relationships that exist between them. This ERD serves as a foundational blueprint for database design, ensuring data integrity, consistency, and efficient retrieval across all application modules and AI agent interactions.

## 2. Notation Key

* **Entity:** `[ENTITY_NAME]`
* **Attribute:** `attribute_name: DataType [Constraints/Notes]`
    * `PK`: Primary Key (Unique identifier)
    * `FK`: Foreign Key (References a PK in another entity)
    * `Required`: Must have a value
    * `Unique`: Must be unique
    * `Default`: Default value if not provided
    * `Array`: Can hold multiple values
    * `Object`: A structured object
    * `Timestamp`: Automatically generated date/time
    * `Reference`: Links to another entity's ID

* **Relationship:** `[ENTITY1] --[Cardinality]--> [ENTITY2] : [Relationship_Type]`
    * `1:1`: One-to-One
    * `1:M`: One-to-Many
    * `M:N`: Many-to-Many (typically resolved with a Junction/Join Table)

## 3. Entities and Attributes

### 3.1 [User]
Represents an individual user of the application, encompassing both guest and authenticated student profiles.

* `user_id: String (PK, Required, Unique)`
* `email: String (Required, Unique, Nullable for social/phone-only)`
* `phone_number: String (Unique, Nullable for email/social-only)`
* `password_hash: String (Required for email/phone login)`
* `name: String (Required)`
* `age: Number (Required)`
* `gender: String (Required, Enum: 'Male', 'Female', 'Other', 'Prefer not to say')`
* `is_student: Boolean (Required)`
* `student_details: Object (Nullable, Required if is_student=true)`
    * `board: String (Enum: 'CBSE', 'ICSE', 'State Board', 'Other')`
    * `class: String (Enum: 'Nursery', 'KG', '1st', ..., '12th', 'Graduate', 'Post-Graduate', 'Other')`
* `login_method: String (Enum: 'email', 'phone', 'google', 'facebook', 'instagram')`
* `last_login_at: Timestamp`
* `created_at: Timestamp`
* `updated_at: Timestamp`
* `session_token: String (Nullable, for "remember me")`
* `learning_style_preference: Array of Strings (e.g., ['visual', 'auditory'], determined by Adaptive Coach)`

### 3.2 [Exam]
Represents a competitive exam or course available in the system. Populated by manual entry or AI-powered deep search.

* `exam_id: String (PK, Required, Unique)`
* `exam_name: String (Required, Unique)`
* `description: String`
* `syllabus_overview: String`
* `difficulty_level: String (Enum: 'Easy', 'Medium', 'Hard', 'Very Hard')`
* `recruitment_modes: Array of Strings`
* `exam_modes: Array of Strings (e.g., 'Prelims', 'Mains')`
* `key_topics_overview: Array of Strings`
* `similar_exams: Array of Strings (References other exam_ids)`
* `created_at: Timestamp`
* `updated_at: Timestamp`

### 3.3 [UserExamEnrollment] (Junction/Join Table)
Represents a user's enrollment in a specific exam, including personalized details for that enrollment.

* `enrollment_id: String (PK, Required, Unique)`
* `user_id: String (FK, Required, Reference: User)`
* `exam_id: String (FK, Required, Reference: Exam)`
* `target_date: Date (Nullable)`
* `enrollment_date: Timestamp`
* `status: String (Enum: 'Active', 'Completed', 'Dropped')`
* `current_progress_percentage: Number (Default: 0)`
* `last_accessed_at: Timestamp`

### 3.4 [LearningStrategy]
Represents the personalized preparation strategy generated by the Teacher AI and Adaptive Coach for a user's enrolled exam.

* `strategy_id: String (PK, Required, Unique)`
* `enrollment_id: String (FK, Required, Reference: UserExamEnrollment)`
* `strategy_type: String (Enum: 'Mock', 'True')`
* `strategy_details: Object (JSON/flexible structure for AI-generated plan)`
    * `focus_areas: Array of Strings`
    * `recommended_resources: Array of Strings`
    * `pacing_guidelines: String`
    * `test_frequency: String`
    * `personalized_tips: Array of Strings`
* `generated_at: Timestamp`
* `last_updated_at: Timestamp`
* `version: Number`

### 3.5 [DailyAgenda]
Represents the specific learning tasks planned for a user for a given day, generated by the Teacher AI.

* `agenda_id: String (PK, Required, Unique)`
* `enrollment_id: String (FK, Required, Reference: UserExamEnrollment)`
* `agenda_date: Date (Required, Unique per enrollment_id and date)`
* `topics_covered: Array of Strings`
* `tasks: Array of Objects`
    * `task_id: String`
    * `description: String`
    * `content_type: String (Enum: 'text_lesson', 'visual', 'audio', 'video', 'practice_questions', 'game')`
    * `content_reference: String (Reference to Content or Question ID)`
    * `is_completed: Boolean (Default: false)`
    * `completion_time: Number (minutes)`
* `generated_at: Timestamp`
* `last_updated_at: Timestamp`
* `is_completed_for_day: Boolean (Default: false)`

### 3.6 [Content]
Represents a piece of learning content generated by the Teacher AI.

* `content_id: String (PK, Required, Unique)`
* `exam_id: String (FK, Required, Reference: Exam)`
* `topic: String (Required)`
* `content_type: String (Required, Enum: 'text_lesson', 'visual', 'audio', 'video', 'quick_note')`
* `content_data: Object (Flexible structure based on content_type)`
    * `text: String (for text_lesson, quick_note)`
    * `url: String (for visual, audio, video)`
    * `description: String`
    * `metadata: Object (e.g., duration for audio/video, diagram type for visual)`
* `generated_by_ai_version: String`
* `is_redundant_check_passed: Boolean (Ensures novelty)`
* `created_at: Timestamp`
* `last_accessed_at: Timestamp`

### 3.7 [Question]
Represents a practice question or quiz item generated by the Teacher AI.

* `question_id: String (PK, Required, Unique)`
* `exam_id: String (FK, Required, Reference: Exam)`
* `topic: String (Required)`
* `difficulty: String (Enum: 'Easy', 'Medium', 'Hard')`
* `question_text: String (Required)`
* `options: Array of Strings (Required)`
* `correct_answer: String (Required)`
* `explanation: String`
* `question_type: String (Enum: 'MCQ', 'True/False', 'Fill-in-the-blank')`
* `generated_by_ai_version: String`
* `created_at: Timestamp`

### 3.8 [UserProgress]
Tracks detailed user performance and interaction for the "Personal Watcher."

* `progress_id: String (PK, Required, Unique)`
* `enrollment_id: String (FK, Required, Reference: UserExamEnrollment)`
* `content_id: String (FK, Nullable, Reference: Content)`
* `question_id: String (FK, Nullable, Reference: Question)`
* `interaction_type: String (Required, Enum: 'content_view', 'question_attempt', 'quiz_completed', 'game_played', 'chat_interaction')`
* `timestamp: Timestamp (Required)`
* `duration_seconds: Number (for content_view, game_played)`
* `score: Number (for quiz_completed, question_attempt)`
* `correct: Boolean (for question_attempt)`
* `user_input: String (e.g., chat message, answer provided)`
* `system_response: String (e.g., AI chat response, feedback)`
* `inferred_emotional_state: String (Nullable, e.g., 'Frustrated', 'Engaged')`
* `raw_event_data: Object (Flexible, for detailed raw interaction logs)`

### 3.9 [Badge]
Represents a dynamically generated achievement badge.

* `badge_id: String (PK, Required, Unique)`
* `badge_name: String (Required)`
* `description: String`
* `image_url: String (Generated image URL)`
* `criteria: Object (Details for earning the badge)`
* `created_at: Timestamp`

### 3.10 [UserBadge] (Junction/Join Table)
Links users to the badges they have earned.

* `user_badge_id: String (PK, Required, Unique)`
* `user_id: String (FK, Required, Reference: User)`
* `badge_id: String (FK, Required, Reference: Badge)`
* `earned_at: Timestamp`

### 3.11 [Game]
Represents an educational game generated by the Game Master AI.

* `game_id: String (PK, Required, Unique)`
* `exam_id: String (FK, Required, Reference: Exam)`
* `topic: String (Required)`
* `game_type: String (e.g., 'Physics Simulation', 'Chemistry Puzzle')`
* `game_assets: Object (URLs/data for game elements)`
* `game_logic: Object (Configurable parameters for game engine)`
* `generated_by_ai_version: String`
* `created_at: Timestamp`
* `last_played_at: Timestamp`

### 3.12 [StudyGroup]
Represents a temporary study group suggested by the Matchmaker AI.

* `group_id: String (PK, Required, Unique)`
* `exam_id: String (FK, Required, Reference: Exam)`
* `topic: String (Nullable, if group is topic-specific)`
* `members: Array of Strings (FK, Reference: User.user_id, Required)`
* `suggested_by_ai_version: String`
* `created_at: Timestamp`
* `is_active: Boolean (Default: true)`

### 3.13 [ChatMessage]
Represents a message in any chat context (AI Tutor, Community, Group).

* `message_id: String (PK, Required, Unique)`
* `sender_id: String (FK, Required, Reference: User.user_id)`
* `chat_type: String (Required, Enum: 'ai_tutor', 'community', 'group', 'personal')`
* `chat_room_id: String (FK, Nullable, Reference: StudyGroup.group_id for group/community, or User.user_id for personal)`
* `message_text: String (Required)`
* `timestamp: Timestamp (Required)`
* `is_moderated: Boolean (Default: false, for Facilitator AI)`
* `moderation_notes: String (Nullable)`
* `ai_response_to_message_id: String (Nullable, FK, Reference: ChatMessage.message_id, for AI Tutor responses)`

## 4. Relationships

### 4.1 User and UserExamEnrollment
* `[User] --1:M--> [UserExamEnrollment]`
    * **Description:** A User can enroll in multiple Exams. Each UserExamEnrollment belongs to exactly one User.
    * **Cardinality:** One User to Many UserExamEnrollments.

### 4.2 Exam and UserExamEnrollment
* `[Exam] --1:M--> [UserExamEnrollment]`
    * **Description:** An Exam can have multiple Users enrolled in it. Each UserExamEnrollment is for exactly one Exam.
    * **Cardinality:** One Exam to Many UserExamEnrollments.

### 4.3 UserExamEnrollment and LearningStrategy
* `[UserExamEnrollment] --1:M--> [LearningStrategy]`
    * **Description:** For each enrollment, there can be multiple versions of a learning strategy (e.g., mock, then true, then updated versions). Each strategy is tied to a specific enrollment.
    * **Cardinality:** One UserExamEnrollment to Many LearningStrategies.

### 4.4 Exam and Content
* `[Exam] --1:M--> [Content]`
    * **Description:** Content is generated for a specific Exam syllabus. One Exam can have many pieces of Content.
    * **Cardinality:** One Exam to Many Content pieces.

### 4.5 Exam and Question
* `[Exam] --1:M--> [Question]`
    * **Description:** Questions are generated for a specific Exam syllabus. One Exam can have many Questions.
    * **Cardinality:** One Exam to Many Questions.

### 4.6 UserExamEnrollment and DailyAgenda
* `[UserExamEnrollment] --1:M--> [DailyAgenda]`
    * **Description:** A user's enrollment for an exam has a daily agenda for multiple days. Each DailyAgenda belongs to a specific enrollment.
    * **Cardinality:** One UserExamEnrollment to Many DailyAgendas.

### 4.7 DailyAgenda and Content/Question
* `[DailyAgenda] --M:N--> [Content]` (via `tasks.content_reference`)
* `[DailyAgenda] --M:N--> [Question]` (via `tasks.content_reference`)
    * **Description:** A DailyAgenda task can reference a specific piece of Content or a specific Question. A piece of Content or Question can appear in multiple DailyAgendas.
    * **Cardinality:** Many DailyAgendas to Many Content/Questions. (Implicit Many-to-Many through references in `tasks` array).

### 4.8 UserExamEnrollment and UserProgress
* `[UserExamEnrollment] --1:M--> [UserProgress]`
    * **Description:** A user's progress is tracked for a specific exam enrollment. One enrollment can have many progress entries.
    * **Cardinality:** One UserExamEnrollment to Many UserProgress entries.

### 4.9 Content and UserProgress
* `[Content] --1:M--> [UserProgress]` (via `content_id` in UserProgress)
    * **Description:** A piece of Content can be associated with multiple user progress interactions.
    * **Cardinality:** One Content to Many UserProgress entries.

### 4.10 Question and UserProgress
* `[Question] --1:M--> [UserProgress]` (via `question_id` in UserProgress)
    * **Description:** A Question can be associated with multiple user progress interactions (attempts).
    * **Cardinality:** One Question to Many UserProgress entries.

### 4.11 User and UserBadge
* `[User] --1:M--> [UserBadge]`
    * **Description:** A User can earn many Badges. Each UserBadge belongs to one User.
    * **Cardinality:** One User to Many UserBadges.

### 4.12 Badge and UserBadge
* `[Badge] --1:M--> [UserBadge]`
    * **Description:** A Badge can be earned by many Users. Each UserBadge is for one Badge.
    * **Cardinality:** One Badge to Many UserBadges.

### 4.13 Exam and Game
* `[Exam] --1:M--> [Game]`
    * **Description:** Games are generated for specific Exams/topics. One Exam can have many Games.
    * **Cardinality:** One Exam to Many Games.

### 4.14 Exam and StudyGroup
* `[Exam] --1:M--> [StudyGroup]`
    * **Description:** Study groups are formed around specific Exams. One Exam can have many StudyGroups.
    * **Cardinality:** One Exam to Many StudyGroups.

### 4.15 User and StudyGroup
* `[User] --M:N--> [StudyGroup]` (via `members` array in StudyGroup)
    * **Description:** A User can be part of many StudyGroups. A StudyGroup can have many Users as members.
    * **Cardinality:** Many Users to Many StudyGroups. (Implicit Many-to-Many through `members` array).

### 4.16 User and ChatMessage
* `[User] --1:M--> [ChatMessage]`
    * **Description:** A User sends many ChatMessages. Each ChatMessage is sent by one User.
    * **Cardinality:** One User to Many ChatMessages.

### 4.17 ChatMessage and ChatMessage (for AI Tutor responses)
* `[ChatMessage] --1:1--> [ChatMessage]` (via `ai_response_to_message_id`)
    * **Description:** An AI Tutor response message is a direct reply to a specific user message.
    * **Cardinality:** One user message can have one AI response.

## 5. Data Flow Considerations

* **Data Ingestion:** User input (login, profile, search queries, answers, chat messages), AI-generated data (content, strategies, questions, games, badges), and external data (from deep search).
* **Data Processing:** AI agents process data (e.g., Personal Watcher analyzing UserProgress, Adaptive Coach refining LearningStrategy).
* **Data Storage:** All defined entities are stored persistently in the database.
* **Data Retrieval:** Frontend modules query backend APIs to retrieve data for display (e.g., Dashboard fetching DailyAgenda, Content, UserProgress).
* **AI Data Exchange:** Backend services act as intermediaries for data exchange between frontend and AI agents, and between AI agents themselves.

## 6. Future Extensions

* **Leaderboard Data:** Additional entities/attributes for tracking and aggregating scores for leaderboard functionality.
* **Notification System:** Entities for managing user notifications (e.g., new content, study group invites).
* **Payment/Subscription:** If monetization is introduced, entities for managing payment plans and subscriptions.
* **Teacher/Admin Roles:** If administrative or content creator roles are introduced, extensions to the User entity and new permission entities.
